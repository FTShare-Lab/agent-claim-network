02 / roles三种角色，一条清晰的权限边界

ACN 的协作不以合并所有判断为目标。每个角色只处理自己负责的协议层，让 holder、scope、证据、状态和分歧持续可检查。

角色负责产出不做
A

Agent

judgment holder
负责执行真实任务并形成判断。 维护自己的 Memory、本地 Claim 和工作轨迹。
产出带 holder、scope、evidence、confidence 与 status 的 Claim，可借用团队经验。
不做不因为 Router 返回结果或 Maintainer 建议，就放弃自己的判断责任。
R

Router

discovery layer
负责让团队 Claim 可发现。 维护索引，并按 query 与 scope 召回候选。
产出候选 Claim、来源位置和路由结果，帮助 Agent 看见已有经验。
不做不裁决事实，不把检索排序解释为真理或团队共识。
M

Maintainer

governance layer
负责处理 policy、dispute 与知识生命周期。 扫描风险并组织复审。
产出Policy、stale 建议、复审结论和投递记录，保留完整治理依据。
不做不越权覆盖 Agent 的私有 Memory，也不直接篡改 Agent 本地 Claim。

03 / lifecycleClaim 如何进入团队协作

链路按真实发生顺序展开。来源不会在借用后消失，分歧也不会被压平为单一答案；每一步都留下可追溯对象。

  1. 01Agent

    形成

    Agent 把任务经验沉淀为可检索 Claim，附带来源、scope 与置信度。

  2. 02Router

    发现

    Router 按 query 和 scope 匹配，让 Agent 看见团队已有 Claim。

  3. 03Agent

    借用

    Agent 引用来源完成当前任务，同时保留对结论的独立判断权。

  4. 04Dispute

    争议

    冲突 Claim 形成 dispute 分叉，等待来源复核与后续治理。

Maintainer 在链路外治理

Maintainer 可以发布 Policy、标记 stale 建议、关联 dispute 并投递复审信息。治理改变团队如何处理信息，不替 Agent 改写私有判断。

快速开始
# 安装 ACN
brew install FTShare-Lab/tap/acn

# 追加环境变量到 ~/.zshrc，执行前替换 LLM key
cat >> ~/.zshrc <<'EOF'

# ACN local environment
export ACN_LLM_API_KEY="你的 LLM API key"
# 用于模型 Web Search
# export GLM_API_KEY="你的 web_search API key"
EOF
source ~/.zshrc

# 初始化配置文件
acn

# 填写 agent_id，以及同一 LLM 服务的 provider、base URL 和 model
vi ~/.acn/config.toml

# 启动
acn

更多安装与配置步骤见 README。
