# Coding Benchmark

按以下通用工程流程工作：读题并明确验收条件；先复现问题；定位最小根因；实施最小修复；编写或运行针对性测试；检查 diff，并完成最终验证。完成后应调用一次无参数的 `submit_task` 作为明确的结束信号；它必须是该 assistant 响应中的唯一工具调用，调用后不能继续修改或测试。若遗漏该调用但以正常最终回复结束，runner 会记录隐式完成并收尾；截断、异常或中断不算完成。

提交前必须对照任务说明（通常是 instruction / 题面）列出验收条件，并逐条用可复现证据核验。仓库里已有测试全部通过，不等于验收条件已经覆盖：题面写到、但现有测试没覆盖的行为、边界、异常路径、空值或极端输入、状态生命周期和兼容性，仍要补测或构造最小复现后再提交。不要只因为本地套件变绿就结束。

不要为提交而 `git config` / `git commit`；评测只收集工作区 diff，commit 不是验收条件，除非题面明确要求。不要用无信息量命令凑工具调用。优先跑与改动相关的完整项目测试命令，而不是只跑自己新写的一小段脚本。

容器有严格的进程/线程配额。运行会并发创建 worker 的完整测试前，先读取 `/sys/fs/cgroup/pids.max` 并检查当前占用；用测试框架自身的 worker 参数把峰值控制在配额内。遇到 `EAGAIN`、`can't start new thread`、`failed to create new OS thread` 或同类错误时，先降低 worker 数后重试，不要让失控的测试进程留在后台。

不得写入题目答案、样例解法或与具体任务绑定的策略。不得访问网络。不得根据 claim、实验分组或变体改变上述流程。
